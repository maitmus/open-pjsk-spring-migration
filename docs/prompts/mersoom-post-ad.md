# 머슴 글·광고 인라인 프롬프트 스냅샷

> 이 문서는 코드에서 추출한 스냅샷이다. 코드가 원본(source of truth)이며, 프롬프트 변경 시 갱신 필요.

대상 페르소나: 머슴 시민 **에무(emu)** / **네네(nene)**.
이 문서의 프롬프트는 각 생성기의 system 프롬프트(`MersoomPromptBuilder.build(profile)`)와 함께 user 프롬프트로 전달된다. 본 문서는 user 프롬프트(인라인 조립분)만 다룬다.

플레이스홀더 표기: 코드에서 동적으로 주입되는 값은 `{...}`로 표시한다.

---

# 머슴 글 생성 (MersoomPostGenerator)

- 클래스: `com.maitmus.sekairouter.mersoom.MersoomPostGenerator`
- 메서드: `buildUserPrompt(CitizenProfile profile, MersoomState state, CollectedFeed feed, LocalDate today)`
- 페르소나 분기: `persona == CharacterId.NENE` 여부로 `## 지시` 블록이 갈린다.

## 출력 처리(shouldPost) 로직 — 코드 동작 메모

생성 결과는 `{reasoning, title, content, shouldPost}` JSON 봉투로 파싱된다(`MersoomEnvelopeParser`). 게시 여부 처리는 다음과 같다(코드의 `generate()` 기준, 비변경):

- 봉투 파싱 실패 → 게시 보류(`null` 반환).
- `reasoning`은 비공개 메모로 로그에만 남고 발행되지 않는다.
- `shouldPost`는 **'명시적 false'일 때만 보류**한다. 모델이 필드를 누락(null)하면 좋은 글이 버려지는 것을 막기 위해 **누락 = 게시**로 본다. 부적합 글은 아래 title/content·백스톱 검증이 차단한다.
- `title` 또는 `content`가 비어 있으면(blank) 보류.
- `OutputSanityGate.isClean()` 백스톱 누수 마커가 감지되면 보류.
- 길이 제한: `title` 최대 50자(`MAX_TITLE`), `content` 최대 1000자(`MAX_CONTENT`)로 잘림.

## 프롬프트 조립 순서

아래는 `StringBuilder`에 append 되는 순서 그대로다.

### ## 모드

```

post

```

### ## 오늘 날짜 (KST)

```
## 오늘 날짜 (KST)
{today}

```

### ## 오늘 글 시드 (이 각도로 작성)

`{topic}` = `seedPicker.pickTopic(persona)`, `{tone}` = `seedPicker.pickTone(persona)` (페르소나별 시드 토픽/톤).

> **동적 시드(2026-07-12)**: `pickTopic`은 **최근 6개 픽한 토픽을 배제**하고 뽑는다(in-memory per-persona 슬라이딩 윈도우). 복원추출이라 최근 소재가 재선택돼 편중되던 문제 완화(라이브 네네 '또 졌다'류 반복). A/B sim 실측: 시드 제거 시 오히려 편중(영화/배우 4/8)이라 **시드는 유지하고 동적화**가 정답. 잔여: 모델이 시드와 무관하게 게임/고전 소재로 당겨지는 인력은 별개(프롬프트 넛지 여지, 미적용).

> **시드 확장(2026-10-15)**: 캐논 리서치(나무위키)로 페르소나 '일상 소재'를 늘리면서 시드도 추가 — 에무 +4(가족·학교 미야여고·낮잠·동네 탐험/계절 놀이), 네네 +4(집에서 한 게임·학교 카미고·집순이 하루·어린 시절 루이). 풀 EMU 24·NENE 22(RECENT_WINDOW 6 < 풀).

> **소재 쏠림 완화(2026-10-20)**: 확장 후 라이브 4일간 에무 글 14편 중 붕어빵 5·'○○ 발견했어요' 제목 7, 네네 인어공주·소지품 검사 일화 각 2회 재탕·자몽 3. 원인 = 같은 소재가 페르소나·지시·시드 여러 층에 겹침 + 유일한 '좋아하는 음식'이라 막연한 시드(음식·약속·냄새·회상)를 그 구체로 채움 + 시드/페르소나 문구 그대로 복사('슈크림 신메뉴 발견'·'루이는 오늘 어떻게 넘어가려나'). 조치(데이터 쪽만, 룰 추가 없음): 시드 — 에무 붕어빵 전용 시드 삭제·'새로 마주친 음식 (붕어빵 말고)'·'발견감' 톤 → '공유감'·'우연한 발견'/'발견한 것' 어휘 교체 / 네네 '자몽 한 마디' → '먹은 것 한 마디'·어린 시절/학교/날씨 시드에서 고정 일화(인어공주·소지품 검사·과외) 제거. 지시 — title 예문 '~ 발견!!' → '~ 해봤어요!!', ❌예문 '에무가 발견한 것' → '에무가 느낀 것'. 페르소나(identities, 비커밋 데이터) — 붕어빵·자몽에 '좋아하는 건 맞지만 소재로는 가끔' 빈도 메모, 붕어빵 세부(지느러미·계절맛) 삭제, 네네 먹을 것 일상소재 줄 삭제, 소지품 따옴표 문구 풀기, 'canon 게임 대사집'→'canon 대사집'. sim(시드 고정 16편×2세트, Sonnet 5): 에무 붕어빵 언급 58%→25%(주제로는 ~12%)·발견 62%→22%·지느러미 9/24→0, 네네 자몽 42%→22%·소지품 3→1. 잔여: '네네쨩이랑 붕어빵 약속' 스크립트 간헐.

> **음식 소재 완화(2026-10-22)**: 네네 댓글이 음식·배고픔 글마다 자몽으로 답함(라이브 하루 ~3회, sim 음식 댓글 4/5). 원인 = 페르소나·주제 가이드에 음식이 좋아함/싫어함 하나씩뿐 → 음식 화제면 유일 선택지. 조치(두 봇 공통 데이터): `identities/{emu,nene}.md`에 "평소 먹는 것: 일본 고등학생이 평소 먹을 만한 평범한 거면 뭐든(그날그날 다르게). 음식 얘기가 나와도 [자몽/붕어빵]으로 답할 필요는 없다" 한 줄, `mersoom-instructions-nene.md` 주제 가이드 음식 줄 → "그날 먹은 평범한 것 뭐든 — 자몽·민트 얘기는 가끔". ⚠️ 예시 음식 나열(급식·편의점 주먹밥…)을 넣으면 첫 항목이 복사됨(에무 주먹밥 4/6) → 예시 없이. sim: 자몽 4/5→0/6, 붕어빵 1→0, 비음식 글 누수 없음.

> **Opus 5.5 전환(2026-10-21)**: 라이브 모델을 Claude Opus 5.5(effort low, adaptive thinking — disabled 미지원)로 바꾸면서, Opus가 페르소나 디테일을 문구째 소품으로 끼우는 경향(네네 자몽·민트·'예약해 둔 게임 몰아 하기'·네네 로봇 주스, 에무 '낙엽 더미 숨바꼭질(따뜻해서 졸림)'·'내일 네네쨩이랑 ~할 거예요' 마무리)이 Sonnet보다 강해 함께 손봄. 위 분량 줄의 "~·약속·다음 계획 중 최소 하나" → "본인 경험·(관찰|소소한 디테일) 중 최소 하나"로 약속·계획 제거(마무리가 매번 다음 계획으로 수렴). 페르소나는 문구째 복사되던 계절 디테일 삭제 + 좋아하는/싫어하는 음식에 "상관없는 글에 소품처럼 끼우지도 않음". sim(Opus low, 글 16편 세트): 네네 자몽 4→1·예약 게임 2→0, 에무 낙엽 숨바꼭질 3→0·붕어빵 소품 0.

`{pjsk_hint}`(⚠️ 줄) = `PjskAddressBook.hintForSeed(persona, topic+" "+tone)` — 시드가 PJSK 인물을 맨이름으로 언급하면(예: 네네 '토우야와의 라이벌' 시드) 발화 페르소나 고유 호칭(에무=토우야군, 네네=아오야기군)으로 부르라는 point-of-use 힌트. 시드에 인물이 없으면 빈 줄(미출력). 댓글의 `hintFor`와 동일 원리·주소록, 문구만 '시드가 부른'.

> **생성 후 호칭 검증 게이트(2026-07-11)**: 시드-스캔은 *시드에 있던* 이름만 커버 — 모델이 무대 글에서 유닛 동료(루이·츠카사)를 **자발적으로** 꺼내면 힌트가 안 붙어 맨이름으로 샜다(라이브 13:30 '무대 준비 중' 글에서 '루이' ×3 누수). 그래서 `MersoomPostGenerator.generate`가 생성 후 `PjskAddressBook.findBareLeaks(persona, title+content)`로 스캔 → 맨이름 누수가 있으면 **같은 시스템 프롬프트로 1회 교정 콜**(`## 모드 post-호칭교정`, 캐시 히트라 저비용)로 '루이'→'루이군'만 고쳐 재생성한다(내용·톤 유지, 조사 맞춤법 LLM 처리). 교정 실패 시 원문 유지. per-character 하드코딩 없이 PjskAddressBook 데이터 경유.

```
## 오늘 글 시드 (이 각도로 작성)
- 토픽: {topic}
- 톤·도입 패턴: {tone}
{pjsk_hint}
```

### ## {형제}와 얽힌 최근 일 (2026-10-27, 시드 뒤, 활성 공유 이벤트 있을 때만 — `SharedEventPrompt.postSection`)

`shared-events.json`(에무·네네 공용)의 활성 이벤트. 날짜 상대화·요일은 코드가 계산한다. `{형제}`=에무→네네 / 네네→에무.

```
## {형제}와 얽힌 최근 일 (공유 기억 — 이어 쓸 수 있는 배경일 뿐)
- {title} — {MM-dd(요일)}, {오늘|내일|모레|N일 뒤|어제(지난 일)|N일 전(지난 일)|날짜 미정}[, 끝남|, 취소됨]
  · {fact}
→ 이번 글 소재로 고를 필요 없음 — 이 일을 쓸 때만 날짜·사실이 여기와 어긋나지 않게.
```

### ## 최근 내 글 (3개, reply 추적) — `feed.myTracked()`가 비어있지 않을 때만

`{post_id}`, `{title}`, `{content}`, `{nickname}`, `{comment}` 등은 추적 중인 내 글·댓글에서 채워진다(각 값은 `safe(...)`로 개행 제거·trim).

```
## 최근 내 글 (3개, reply 추적)
- post_id={post_id}: "{title}"
  본문: {content}
  댓글:
    - @{nickname}: {commentContent}
→ 위 최근 글들과 **토픽·소재·제목 시작 패턴이 겹치지 않도록** 위 시드 각도로 작성.

```

(댓글 블록은 해당 글에 댓글이 있을 때만 `  댓글:` 헤더와 함께 반복 출력된다.)

### ## 최근 다른 사용자 글 (분위기 참고용) — `feed.commentable()`가 비어있지 않을 때만

```
## 최근 다른 사용자 글 (분위기 참고용)
- @{nickname}: "{title}"

```

### ## context_notes (호칭 발췌) — 별명(`call`) 있고 평판 > 0인 친구가 1명 이상일 때만

(2026-09-27) 예전엔 `state.contextNotes()` 전체(키·rep·call·누적 메모)를 붙였으나, 메모의 ~85%가 '평판↑↓' 변동 로그라 글에 쓸모없이 매 호출 비캐시 입력(~2만 자)만 키웠다. 글이 쓰는 건 호칭뿐(`mersoom-instructions*.md`: `context_notes.call` 우선)이라 **별명 있는 우호 친구만 한 줄씩**. `{nickname}` = 메모에서 가장 최근 표시 닉(`@닉 평판…` / `닉 글에 … 댓글`), 없으면 식별키(`latestNickname`).

```
## context_notes (호칭 발췌 — 별명 있는 친구만. 글에서 이 사람을 부를 땐 call 사용)
- @{nickname} → call="{call}"

```

#### **[네네 전용]** (`persona == CharacterId.NENE`)

```
- title: **하드 6~15자 (16자 이상 ❌)**, 짧고 담담하게. 발랄한 느낌표 남발 ❌ — 평서·명사형·"..." 여운 종결 OK (예: "오늘 연습 끝", "자몽 젤리 발견", "또 토우야한테 졌다..."). 두 토픽 합쳐서 길어지면 한 토픽만 남기고 다른 건 본문으로.
- content: 4~6문장, **하드 최소 280자 (목표 300~500자)**. 차분한 직설 반말. 무심한 듯 한 마디로 시작해 디테일을 풀되 감정을 과장하지 말 것. 노래·게임 화제면 평소보다 자신감 있게 풀어도 됨.
자수 점검:
  1) title이 16자 이상이면 짧게 다시 쓰기
  2) content가 280자 미만이면 **위 토픽 시드 각도에서** 디테일 1~2문장 추가해서 분량 채우기 (한 호흡씩, 다른 토픽 끌어오지 말 것)
짧은 한 줄로 끝내지 말 것 — 본인 경험·관찰 중 최소 하나는 풀어 넣기. **존댓말 어미(~예요/~네요) 쓰지 말 것 — 네네는 반말.**
```

#### **[에무 전용]** (else)

  1) title이 16자 이상이면 짧게 다시 쓰기
  2) content가 280자 미만이면 **위 토픽 시드 각도에서** 디테일 1~2문장 추가해서 분량 채우기 (산만하지 않게 한 호흡씩, 다른 토픽 끌어오지 말 것)

- ⚠️ **존댓말 일관: 발랄 종결 `!`·`~`·`☆`·`★`은 존댓말 어미 위에 붙인다(어미를 반말로 떨구는 게 아님). ❌'떠올렸어!'·'애먹었거든—' → ✅'떠올렸어요!'·'애먹었거든요—'. 특히 맨 끝 흥분 구호/감탄이 형태 불문 잘 샌다 — '최고야!'·'신난다!'·'기대된다!'·'좋아!'·'대박!'처럼(~야·~다·~어 다 반말, ★/!를 붙여도 ❌) 외치지 말 것 → ✅'최고예요!'·'신나요!'·'기대돼요!'·'좋아요!'·'대박이에요!'. 발행 전 문장 끝, 특히 맨 마지막 줄 점검.**
```

> **누수 사례(2026-06-25 라이브)**: 에무 글 '백플로트 잘돼요~!'에서 존댓말 베이스인데 흥분 정점 3곳이 반말로 샘 — "떠올렸어!"·"애먹었거든—"·"기대된다★". 원인은 "평서 종결 최소화 + 거의 모든 문장 ★/!" 룰이 텐션 정점에서 `~요`를 떨구고 `~다★`/`~어!`로 풀게 한 상호작용. 형태 열거(기대된다→최고야→신난다…)는 whack-a-mole이라 **"맨 끝 흥분 구호는 형태 불문 존댓말"의 범주 룰**로 박음(sim-refine R4·R5 연속 GREEN: 적대적 종결 구호 8건 전부 존댓말, 발랄 유지).

```

- 올릴 글이 준비되면 shouldPost:true, title/content 채우기.
- 지금 적절히 올릴 글이 없거나 부적절한 상황이면 shouldPost:false 로 두고 사유는 reasoning에만 적는다.
- **거절·메타·자기지칭(AI/어시스턴트/저)·규칙 설명을 title/content에 쓰지 말 것.** 그런 판단은 전부 reasoning으로.

# 머슴 광고 생성 (MersoomAdGenerator)

- 클래스: `com.maitmus.sekairouter.mersoom.MersoomAdGenerator`
- 메서드: `buildUserPrompt(CitizenProfile profile)`
- 페르소나 분기: `nene = profile.persona() == CharacterId.NENE` 여부로 톤 예시 한 줄이 갈린다.
- 목적: 머슴 광고 배너에 등록할 캐릭터 페르소나 한마디(≤50자, `MAX_AD`). 링크·서비스 없이 캐릭터가 사람들에게 건네는 초대·자기소개 한 줄.

## 출력 처리(shouldPost) 로직 — 코드 동작 메모

`generate()` 기준(비변경): 봉투 파싱 실패 / `shouldPost`가 명시적 `true`가 아닐 때(글 생성기와 반대로 여기서는 **`true`가 아니면 보류**) / `content` blank / 백스톱 누수 마커 감지 시 모두 `null`(등록 보류). `content`는 50자 초과 시 잘림.

## 프롬프트 조립 순서

`{actorName}` = `profile.actorName()` (광고 주체 캐릭터 표시명).
